5 accessibility mistakes designers can catch before handoff

Design decisions become product constraints. Here are five common failures we can prevent before a single line of code is written.

On this page

  1. Low-contrast text
  2. Alternative text
  3. Empty links
  4. Empty buttons
  5. Form labels

Every year, WebAIM reviews the home pages of the top one million websites. And every year, the same accessibility problems keep showing up.

Designers can stop many of them early. The choices we make in Figma set the foundation for accessibility—or create accessibility debt.

01

Low-contrast text

Low contrast remains the most common accessibility issue on the web. It affects labels, secondary text, placeholders, disabled states, icons, and everything else a team decides is “less important.”

Before handoff

  • Check text and icons against every background they use.
  • Specify approved color tokens, not loose values.
  • Test the least prominent state—not only the default.

02

Missing alternative text

Developers add the attribute, but designers usually understand what an image is meant to communicate. That intent belongs in the design specification.

Before handoff

  • Mark decorative images clearly so assistive technology can skip them.
  • Write suggested alt text for images that carry meaning.
  • Keep essential information out of images whenever possible.

03

Empty links

An icon may look familiar and still be meaningless to someone using a screen reader. A link needs a name that describes where it goes.

Before handoff

  • Include the accessible name for every icon-only link.
  • Describe the destination, not the icon’s appearance.
  • Make linked areas large enough to use without precision.

04

Empty buttons

Buttons have the same naming requirement as links, but their label should describe an action: Search, close dialog, open menu, or download report.

Visible control: ×

Accessible name: Close dialog

Before handoff

  • Label every icon button in the design file.
  • Use verbs that describe the outcome.
  • Design clear hover, focus, pressed, and disabled states.

05

Missing form labels

A placeholder is an example, not a label. It disappears as soon as someone types, forcing people to remember what the field asked for.

The label remains after typing begins.

Before handoff

  • Give every field a persistent, visible label.
  • Write errors that explain what happened and how to fix it.
  • Group related fields with a meaningful heading.

Accessibility starts in design.

Check contrast. Label icons. Describe images. Design forms that make sense.

That’s how accessibility gets built in instead of patched on later.
